Agni Box Host — UI layer

How the persistent computer and its screen handoff should be built, and what it costs on each OS. Design memo, Agni-Bot, 17 Oct 2026.

Three tiers, one handoff UI. All the OS-specific work lives inside the last tier — everything above it is portable, which is why the UI layer can be designed before the platform question is settled.

1 · Two different products are being conflated

Agni Box

Isolated, disposable, streamable. Its own X display, its own browser profile, its own Unix user. It cannot reach the host. Lives on bb-1.

This is the GrokBot clone. On a Mac you test it by running Linux in a VM — the Mac stays a client, not a host.

Agni Screen

Your actual desktop. Real logins, real apps, real files. No sandbox, no isolation.

A different product with a different consent model: TCC grants on macOS, driver signing on Windows. Opt-in, never the default.

Every design question below resolves differently depending on which of these you mean, so it is worth naming which one a given piece of work serves. The handoff UI is shared; the trust story is not.

Chromium is the portable layer. Because the browser behaves identically on all three OSes, tiers 0 and 1 give you one handoff UI everywhere. Only tier 2 forks by platform.

3 · Where the pieces sit

4 · Control is a lease, not a toggle

Both sides write to the same screen, so input from anyone who is not the current lease owner must be rejected server-side, not merely hidden in the UI.

This is the model T3's own preview tabs already run — control.owner: agent | human | unclaimed with a generation counter — and it is worth copying rather than inventing.

5 · Protocol additions

All additive, so no PROTOCOL_VERSION bump and existing clients keep working:

DirectionFrameNotes
c→sscreen.watchSubscribe to a session; carries quality and fps hints.
c→sscreen.take / screen.releaseHuman acquires or returns control.
c→sscreen.inputPointer, key, paste. Rejected unless the sender holds the lease.
s→chuman.requestThe pause. {requestID, sessionID, reason, url, buttons}.
s→chuman.resolvedresumed | timeout | cancelled.
s→cscreen.state{display:{w,h}, owner, generation}.
s→cscreen.frameThe payload. Base64-in-JSON costs +33% — plan a binary channel.

Two costs specific to this repo

  • apps/mac/Sources/AgniProtocol/Frames.swift mirrors packages/protocol/src/frames.ts by hand, so every frame above is two edits plus tests on each side. Consider generating the Swift mirror — the fixtures script already exists.
  • screen.frame must never be persisted to the message store or fed back into model context. Pixels can contain passwords, and a rendered page can carry injected instructions, which the untrusted-input rule forbids. Handoff pixels go to the human, not the model.

7 · The three permission stories

Linux — free, if you isolate

Xvfb :99 -screen 0 1280x800x24 -dpi 96, then openbox, then Chromium with --user-data-dir on the persistent volume and --remote-debugging-port=9222 on loopback. Pin DPI at 96 so capture pixels equal CSS pixels 1:1 — that is the property that stops buttons from shifting under the agent.

Drop -ac and use an xauth cookie. Run x11vnc -display :99 -localhost -rfbauth, never -nopw outside a scratch container. Give the box a dedicated agni-box user, a cgroup v2 memory cap, and bubblewrap around Chromium, with no host home mounted. XTEST input is seen by every client on that display — safe on an isolated :99, never on :0.

Wayland is a later option (weston --backend=headless + wayvnc, input via ydotool or libei). Do not start there.

macOS — two grants and a re-consent nag

There is no Xvfb equivalent. XQuartz is an X11 server, but it only hosts X clients — it cannot hold your macOS desktop.

Screen Recording covers capture via ScreenCaptureKit; Accessibility covers CGEventPost into other apps. Two separate grants, neither scriptable, and macOS 15 re-prompts for screen recording periodically — hostile to an unattended agent.

The detail that bites: TCC identity binds to a code signature and bundle. A bun run serve daemon inherits the terminal's identity and can silently lose grants after a rebuild. Driving the Mac wants a signed .app, which is a real tension with the current daemon model.

Recommendation: for v0 do not build a macOS host. Run the Linux box host inside Lima, OrbStack or UTM and keep the Mac a client. That is the real deployment, and it tests the real thing.

Windows — session 0 will fight you

A Windows service cannot see or drive the interactive desktop. The host must run as a logged-on user process, so an unattended reboot has no desktop unless you autologon or supply a virtual display.

That display is an IddCx indirect display driver, and it needs test-signing or a signed driver — with Secure Boot on, that is the single biggest friction on the platform. Then WGC for capture and SendInput for input, with uiAccess plus a signed binary in Program Files before it can touch an elevated window.

Pragmatic shortcut for a personal box: an RDP session creates a desktop, and tscon /dest:console disconnects the viewer while keeping it alive. Hacky but well-trodden. Better still, a WSL2 or Hyper-V Linux guest drops you back onto the Linux path you already have.

8 · The UI answer

The pane is not an <iframe> pointing at port 6080. That is a second origin with a second auth model outside hello and device tokens, it is not sequence-numbered so it cannot resync, it gives up replay, audit and redaction, and it enforces no lease — the human can click while Agni is mid-click.

Instead: the box host speaks plain RFB or H.264 on loopback only, the server proxies it into screen.* frames, and the client renders it as a native pane. One auth model, replay, audit, redaction, and a lease the browser cannot bypass — and the Android client gets handoff for free.

In the Mac app, start with a WKWebView running noVNC's client against the app's local bridge, skinned to the existing design tokens: charcoal canvas, ember while Agni drives, amber while it waits on you, and a sentence rather than a colour saying what is happening.

9 · Sequencing and open risks

The order is forced, and it is not the order you would guess. You cannot design screen.* frames until the transport shape is fixed, and the transport shape — server proxy versus direct iframe — is the only decision here that is expensive to reverse. Everything else, including which tier, which OS and which codec, is swappable behind it.

  1. Fix the transport shape. Proxy through apps/server. This is nearly irreversible and it gates the frames.
  2. Build tier 0, not tier 1. Not because it is easier, but because it is the only tier that unblocks the protocol: a headless Chromium over CDP exercises human.request → lease → screen.input → human.resolved end to end, identically on this Mac and on bb-1 later. Xvfb and openbox are an afternoon of work after the loop is proven.
  3. Measure the tactile risk before committing to RFB. Handoff over Tailscale from a phone is a low-frame-rate JPEG stream with a round trip attached. Clearing a CAPTCHA or typing a 2FA code through that may simply feel awful, and no architecture fixes it. Put a real challenge in front of the tier 0 loop and try it from a phone on cellular. Under roughly 5 fps or over roughly 250 ms of input echo means H.264 over WebRTC instead of noVNC, which changes what the server proxies.
  4. Add the auth branch. Turnstile needs pixels and a pointer. Most 2FA prompts need your phone — a TOTP code, an SMS, a passkey tap. Streaming a desktop to type six digits is a lot of machinery for a deeplink and a number field. Branch human.request so the auth case renders a small purpose-built card in the thread and the screen pane is reserved for cases that truly need a screen.

Keep the box's shell in the box. If the agent has both a sandboxed desktop and a shell tool, and that shell is the host's shell, then approval-gating bash is undermined by a screen you can click through. Two trust domains, two stories: the box host's shell lives inside agni-box, the host's shell stays approval-gated. Worth writing into AGENTS.md when this lands, because it is the kind of rule that erodes quietly.
