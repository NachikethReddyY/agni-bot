Product and runtime plan

Chat should answer.
Tasks should finish.

Keep Agni’s fast conversational path simple. Give multi-step work its own durable run, visible progress, and a real completion check.

What is going wrong now

Every regular chat send enters the same tool-enabled loop. That loop can treat a sentence like “I’ll research this…” as the final answer when the model returns prose without a tool call. It also has a two-minute timeout, unbounded step and token constants, and no required check that the requested result was produced.

A mid-stream provider failure was also marked as a successful end. The client then had no honest signal that the work stopped partway through.

Split the work into two paths

CHAT

Ordinary questions

  • One bounded model call, no tools by default.
  • Stream the answer immediately; keep the instant lane fast.
  • If the request needs tools or sustained work, offer to run it as a task.
TASK RUN

Research, creation, and multi-step work

  • Create a durable run with a goal, steps, checkpoints, and outputs.
  • Show concise action updates, tool results, approvals, and waits.
  • Verify the requested deliverable before marking the run complete.

Task lifecycle

SIDE STATEWaiting for input or blocked can happen during execution; explain why and resume from the last checkpoint.

Progress reports say what Agni did and what happens next. They do not expose private chain-of-thought.

Runtime rules

RuleBehavior
Completion is evidence based“Create a file” completes only after the file exists and can be opened. Research completes with the requested findings and source links. No “done” state for a promise or partial draft.
Runs survive reconnectsPersist task status, current step, tool call, result, and output references. Resume from the last safe checkpoint after an app or server restart.
Limits are explicitUse configurable step, time, and spend budgets. Pause safely at a boundary, explain the limit, and let the user resume or narrow the goal.
Failures stay honestKeep partial output, mark the run failed or waiting, show a useful cause, and offer a safe retry from the last checkpoint.
Use the right executorRoute repository coding to ACP when available. Keep Agni’s coordinator small; do not turn the chat loop into a general coding harness.
Progress is protocol dataAdd structured task lifecycle events and render them as a compact, collapsible activity card. Keep user messages and task updates visually distinct.

Build order

P0

Stop lying about turn state

Remove the streaming caret, preserve partial output, show failures and timeouts as incomplete. Done in the current working changes; restart the server to activate its part.

P1

Restore the fast chat lane

Route ordinary messages through one call without tools. Add a clear “Run as task” path for work that needs tools or several steps.

P2

Add durable task runs

Store goal, status, checkpoints, progress events, approvals, and output references. Make runs resumable after reconnect or restart.

P3

Add verification and specialized executors

Define a completion check per task, route coding to ACP, and surface incomplete work with resume or retry actions.

First end-to-end proof: ask Agni to research a question and create an HTML document. The UI should show each meaningful action, link the finished file, and mark it complete only after checking that the file was written.
Plan grounded in the current Agni client and server behavior. No protocol or executor redesign has been implemented yet.
